# 上线操作步骤

## 阶段一：准备 GitHub

1. 确认 `Hevenlunch/UnderPanda` 仓库为空或只保留 README。
2. 将当前网站源码提交到 `main`。
3. 检查仓库中不包含 `.env`、Token、AccessKey 或本地绝对路径。
4. 开启 GitHub 两步验证。

## 阶段二：Cloudflare Pages 测试站和 CMS

1. 在 Cloudflare 创建 Pages 项目并连接 `Hevenlunch/UnderPanda`。
2. 构建命令设置为 `pnpm build`。
3. 输出目录设置为 `dist`。
4. 设置 Node.js 和 pnpm 版本。
5. 先完成不含 CMS 的静态站点部署测试。
6. 再部署 Decap CMS 的 `/admin/`。
7. 创建 GitHub OAuth App。
8. 部署 Cloudflare Worker OAuth 代理。
9. 将 OAuth 地址配置为 Decap 的 `base_url`。
10. 测试登录、修改、上传图片、发布和回滚。

## 阶段三：阿里云生产站

1. 购买阿里云 OSS 和 CDN。
2. 创建专用 RAM 用户。
3. 只授予 OSS 指定 Bucket 和 CDN 刷新权限。
4. 将 AccessKey 写入 GitHub Actions Secrets。
5. 配置 GitHub Actions 构建并同步 `dist` 到 OSS。
6. 配置 OSS 静态网站托管。
7. 配置 CDN 源站和缓存规则。
8. 使用默认域名做第一轮访问测试。

## 阶段四：正式域名和备案

1. 在阿里云购买域名。
2. 按中国大陆要求进行 ICP 备案。
3. 将域名 CNAME 指向阿里云 CDN。
4. 配置 HTTPS 证书。
5. 将 Decap OAuth 回调和站点域名更新为正式域名。
6. 再次测试 PC、手机、图片上传和发布。

## 阶段五：上线后维护

- 内容更新：通过 Decap 后台提交。
- 代码更新：通过 Codex 或本地 Git 提交。
- 每次发布后检查 GitHub Actions 状态。
- 出现问题时回滚到上一个可用的 Git commit。
- 定期检查图片体积和仓库大小。
