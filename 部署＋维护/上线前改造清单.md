# 上线前改造清单

## 一、必须完成

- [ ] 将字体、标题缩放、模块标签缩放、模块介绍缩放、正文字号、行高和间距从 localStorage 迁移到 Git 跟踪的 JSON。
- [ ] 确认所有线上会显示的样式都有 `site.json` 默认值，不依赖当前浏览器缓存。
- [ ] 将 `src/content/site.json` 映射为 Decap CMS 可以安全编辑的结构。
- [ ] 对 CMS 未配置字段进行保护，避免保存时丢失 JSON 数据。
- [ ] 将现有本地 DEV 上传接口替换为 Decap 媒体库或 Cloudinary 等外部媒体服务。
- [ ] 统一上传目录为 `public/images/uploads/`，公开路径为 `/images/uploads/`。
- [ ] 为图片增加长边、格式和体积限制。
- [ ] 确认生产构建不会包含可编辑后台、开发服务器路径或本地保存接口。
- [ ] 加入构建检查：TypeScript、Vite build、必要页面结构检查。
- [ ] 加入 GitHub Actions 自动部署。
- [ ] 加入部署失败通知。
- [ ] 确认至少有两次发布回滚测试。

## 二、建议完成

- [ ] Decap 开启编辑工作流，发布前可以预览。
- [ ] 增加 staging 地址，用于正式发布前检查。
- [ ] 图片较多时接入 Cloudinary 或 Uploadcare。
- [ ] 引入图片懒加载和尺寸优化检查。
- [ ] 增加站点地图、robots.txt、基础 SEO 信息。
- [ ] 增加访问统计，但不要记录敏感信息。
- [ ] 自定义 404 页面。
- [ ] 检测手机端、PC 端和控制台错误。

## 三、后台权限原则

- [ ] 公开网站只读，访客不可访问 CMS 编辑权限。
- [ ] GitHub OAuth Client Secret 只保存在 OAuth 代理服务端。
- [ ] 阿里云 AccessKey 只放在 GitHub Actions Secrets。
- [ ] 使用专用 RAM 用户，不直接使用阿里云主账号 AccessKey。
- [ ] GitHub 开启两步验证。
- [ ] 不把 `.env`、密钥文件、Token 提交到 Git。

- [ ] 基本信息和地址信息。
- [ ] 首屏文案和最近在做什么。
- [ ] 关于我。
- [ ] 摄影分类和照片。
- [ ] 爱好及其照片。
- [ ] 旅行城市、顺序、路线和照片。
- [ ] 工作理念。
- [ ] 联系链接。
- [ ] appearance 外观配置。
- [ ] typography 字体配置。
